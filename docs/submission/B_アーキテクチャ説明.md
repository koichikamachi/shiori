**設計の中心は「生成AIに判断させない」ことです。**

法律の手続で誤った案内をすると実害が出ます。手続の順序、不可逆の判定、期限の計算は、すべて決定論的なPythonが行います。Geminiが担うのは、言葉づかいと、制度を調べて修正案を出すことだけです。

**構成**

- `data/nodes/*.json` — 地図。64ノード。前後関係・不可逆・期限・相談先
- `src/engine/expr.py` — `exists_if` の専用パーサ。`eval` を使わず、誤りは例外にする（黙って消さない）
- `src/engine/engine.py` — 状態5値とDAG判定
- **Gemini API** — 家族への連絡文、専門家への相談メモ
- **ADK** — 制度追従エージェント。公的資料を調べ案を出す
- **Cloud Run** — ステートレス。DBを持たず、状態はブラウザにのみ置く

**間違いを、人ではなく機械が落とす**

- `tools/lint_nodes.py` — 未定義参照、循環、条件式の誤り、検証状態の矛盾
- `pytest` 36本 — 設計の急所を固定。テストを書いたら意図的にコードを壊し、捕まるかを試す（実際に一度、素通りした穴が見つかりました）
- `verification_status` 四段 — 確かめていないものに確認日を入れると Lint で落ちる

**確かめていないものを、確かめたように見せません。** 64件中62件は専門家未確認であり、画面にもそう表示します。

**エージェントが直せるのは、案を出すところまでです。** JSONを直接書き換えさせません。Lintとテストを通し、人が承認してから反映します。地図をAIに書き換えさせたら、決定論が崩れます。
