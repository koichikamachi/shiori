## 1. 基本設計思想（Architecture & Design Philosophy）

### 1.1 「死後」から「生前（終活）」への視点転換

- **現状の課題：**
  大切な方を亡くした直後の遺族は極度の動揺の中にあり、自らWebを開いて冷静に体系的な手続を調べる余裕は乏しい。現行の「遺された人の地図」という切り口だけでは、最も冷静に手続と向き合えるはずの層へ届かない。
- **新たな核（終活の逆算）：**
  「自分が旅立ったあと、家族は何に直面するのか」を知りたい本人（終活層）を第一の読者とする。
  自分がメモを1枚残すだけで、残された家族が直面する難所（未確認項目や法的手続きの迷路）が消え、「標準ルート」が「短縮ルート」へと劇的に変わる体験（逆算の効用）を提供する。

### 1.2 造形規範：GOV.UKの明晰さ × 上質なエディトリアル装丁

- **脱・エンジニア地下鉄図：**
  CSSで描いた丸アイコンを線で結ぶだけの地下鉄メタファーを脱却する。利用者が求めているのは「路線のグラフィック」ではなく、「何が急所であり、どの順序で進むべきか」という情報の秩序である。
- **文字の息づかい（タイポグラフィ）：**
  デジタル特有の無機質さを排し、一冊の上質な岩波単行本や文芸誌を開いたような静謐さと、英国GOV.UKが誇る「極限の判読性（Cognitive Simplicity）」を融合する。

## 2. カラーパレット & タイポグラフィ規範

### 2.1 カラースケール（Design Tokens）

冷たいデジタルホワイト（`#ffffff`）を排し、紙の温もりを感じさせる生成り色を基調とする。

| トークン名 | カラーコード | 用途 |
| :--- | :--- | :--- |
| `--color-bg-canvas` | `#fcfbf7` | 画面全体の背景色（淡い生成り和紙色） |
| `--color-bg-card` | `#ffffff` | ステップカード、ドロワーの背景（純白で浮かせる） |
| `--color-text-primary` | `#1a1a1a` | 主見出し、重要本文（完全な黒ではなく濃い墨色） |
| `--color-text-secondary` | `#595959` | 補足説明、メタデータ、ステップ番号 |
| `--color-border-subtle` | `#e8e6df` | 境界線、カード枠線 |
| `--color-accent-gov` | `#0b0c0c` | GOV.UK風の太い左アクセントバー（標準ステップ） |
| `--color-alert-crimson` | `#9e2a2b` | 不可逆ノード（預金・放棄・地雷）の警告アクセント |
| `--color-safe-moss` | `#2d6a4f` | 一次資料合致・短縮ルートの肯定色 |

### 2.2 フォントスタック（Typography）

- **大見出し・宣言文（エディトリアル）：**

  ```css
  font-family: "Yu Mincho", "游明朝", "Hiragino Mincho ProN", "BIZ UDPMincho", serif;
  ```

  ※ わずかに文字間（`letter-spacing: 0.08em;`）を空け、品格を持たせる。

- **本文・操作系・監査ログ（高い視認性）：**

  ```css
  font-family: -apple-system, BlinkMacSystemFont, "Yu Gothic", "游ゴシック", "Hiragino Sans", sans-serif;
  ```

  ※ 行間は `line-height: 1.8;` を確保し、疲れた目でも自然に追えるリズムを保つ。

## 3. 画面構造とコンポーネント詳細仕様

### 3.1 トップ画面（ランディング）の再構成

#### A. ヒーローエリア（静謐な呼びかけ）

画面上部に長文の注記を置かず、一冊の本の扉のように配置する。

```html
<header class="editorial-hero">
  <h1 class="brand-title">しおり</h1>
  <p class="hero-tagline">
    終活をはじめたい方へ。そして、大切な家族のために。
  </p>
  <p class="hero-subtext">
    自分が旅立ったあと、家族はどのような道を歩むのか。<br>
    迷いを減らすための手続と期限を、一枚の地図に描きました。
  </p>
</header>
```

#### B. 2つの扉（ナビゲーション・ゲート）

「終活（事前）」と「遺族（直後）」の2つの入り口を堂々と並べる。

```text
┌─ 扉1：ご自身の終活として ─────────────────────────────────────┐
│ 【家族を迷わせないための地図】                                 │
│  ・あなたが何も残さなかった場合に家族がたどる「標準の道」     │
│  ・メモを1枚残すだけで家族の手続きが軽くなる「短縮の道」       │
│  [ 地図を開いて、家族の道のりを確かめる（10日目・短縮/標準） ] │
└───────────────────────────────────────────────────────────────┘

┌─ 扉2：もしも、大切な方を見送られたばかりなら ─────────────────┐
│ 【いま、立ち止まるための地図】                                 │
│  うろたえるのは当然です。まずは葬儀社に頼ってください。       │
│  落ち着いたあと、今日決めるべきことだけを静かに確認できます。   │
│  [ 遺族のための最短ルートを見る（1日目） ]                    │
└───────────────────────────────────────────────────────────────┘
```

#### C. フッター側の信頼性ブロック

制作趣旨や「すること・しないこと」は、画面下部に上質な2カラムで端正にレイアウトする。

### 3.2 地図画面（ステップ・カード型インフォグラフィック）

従来の路線図丸アイコン（CSS二重丸）を廃止し、GOV.UK の Step by step navigation に倣った左線付きステップカードへ移行する。

#### A. ステップカードの構造

- **標準カード（通常手続き）：** 左側に太さ `4px` の濃墨色バー。
- **不可逆カード（地雷駅）：** 左側に太さ `4px` の深紅（`#9e2a2b`）バー ＋ 小さな「不可逆」バッジ。

```html
<article class="step-card critical-gate">
  <div class="step-card-header">
    <span class="step-timing">死の直後・最優先</span>
    <span class="badge-irreversible">不可逆な局面</span>
  </div>
  <h2 class="step-card-title">故人の預金に触る前に知っておくこと</h2>
  <p class="step-card-summary">
    遺産分割前の独断引き出しは、法定単純承認や親族紛争を招く恐れがあります。
  </p>
  <div class="step-card-action">
    <span class="action-label">今日の指針:</span>
    <span class="action-text">原則口座には手を付けず、現状を維持する。</span>
  </div>
</article>
```

#### B. 「終活シミュレーション」トグルスイッチ

地図画面の上部に、切り替えスイッチを新設する。

- **［ 本人のメモ：なし（標準） ］** ➔ 全駅がそのまま表示される。
- **［ 本人のメモ：あり（短縮） ］** ➔ 本人が生前に残した情報により、財産調査や口座特定などの難所カードが「通過済み（スキップ）」として淡くグレーアウトし、家族の道のりが劇的に圧縮される演出を行う。

### 3.3 詳細ドロワー（3層のレイヤード・パネル）

駅（カード）をクリックした際に開くドロワーは、3つの明確な目的を持ったセクションで構成する。

```text
┌─ ドロワーパネル ───────────────────────────────────────────┐
│                                                            │
│ ［第1層：遺族の行動指針（手引き）］                       │
│  ・【事実】【ただし】（不可逆性の提示）                    │
│  ・今日やること（動詞による具体的な指示）                  │
│  ・「〜事前に専門家に相談すべき事柄です」                  │
│                                                            │
│ ［第2層：生前に残せる備え（終活アクション）］【新設】      │
│  ・「元気な今、あなたが書き残せること」                    │
│    例：通帳の保管場所と、仮払い制度（民法909条の2）の       │
│        存在を記した一筆をノートに挟んでおく。              │
│                                                            │
│ ［第3層：AI安全性・品質保証レポート（内部統制）］         │
│  ・自律監査プロセスのステップバー                          │
│  ・公的発表（.go.jp）との逐語一致検証結果                  │
│  ・七つの関門適合レポート                                  │
└────────────────────────────────────────────────────────────┘
```

## 4. データ設計（Schema）への追従指針

この新UIを支えるため、`node.schema.json` の各ノード定義に将来的に追加すべきフィールド：

```json
{
  "pre_mortem_action": {
    "summary": "生前に本人が残せる備えの一筆",
    "note_template": "【家族への書置文例】私の口座は○○銀行○○支店にあります。凍結後、葬儀代等が必要な場合は勝手に下ろさず、窓口で『仮払い制度』を申請してください。",
    "clears_node_id": "SURV_WARN_DEPOSIT"
  }
}
```

本人がこの `pre_mortem_action` を完了（または「メモを残した」）と設定することで、遺族側の当該ノードが解決済み（短縮）へと遷移するロジックを構成する。
